GitHub 계정에 저장소 접근 권한이 있어야 합니다. 터미널에서:

```sh
git clone https://github.com/stewberry326/super-vision-pose-lab.git
cd super-vision-pose-lab
brew install uv ffmpeg
./start.command
```

브라우저에서 http://127.0.0.1:8501 을 여세요. 시작 스크립트가 Python 3.12 가상환경, 고정 버전 패키지, 검토한 TAP 소스를 설치합니다. 최초 설치와 모델 다운로드에는 인터넷과 수 GB의 여유 공간이 필요합니다. 모델 가중치는 처음 사용할 때 다운로드합니다. Apple Silicon Mac에서 검증했으며 다른 OS는 검증하지 않았습니다.

촬영 영상·환자 이미지·분석 결과·모델 가중치는 Git에 포함하지 않습니다. 팀의 승인된 경로로 영상을 별도 전달받아 앱에서 업로드하거나 로컬 경로를 입력하세요. 영상은 외부 추론 서버로 전송하지 않으며 Streamlit 사용 통계도 비활성화했습니다.

업데이트: `git pull` 후 다시 `./start.command`. 의존성이 바뀌었으면 `uv pip install --python .venv/bin/python -r requirements.txt`를 실행하세요.

테스트: `.venv/bin/python -m pytest -q`.

`visionos/TAPValidation.xcodeproj`는 별도 실험용 샘플입니다. Python 앱 전체를 visionOS로 이식한 것은 아닙니다. 저장소에 대형 Core ML 가중치는 포함하지 않습니다. macOS에서 다음으로 생성할 수 있습니다.

## 사용 순서

1. 영상 경로를 입력하거나 MP4/MOV를 업로드합니다.
2. 분석 구간을 조절하고 **구간 시작 시점**에서 `사람 찾기`를 누릅니다.
3. 환자를 클릭하거나 번호로 선택하고 `록온`합니다. 분석은 선택한 프레임부터 시작합니다.
4. 모델과 보정 설정을 선택하고 분석합니다. 초반에는 두 모델·10fps 기본값을 권장합니다.
5. 결과 탭에서 같은 시점의 관절, 원본/보정 그래프, 모델별 비교 영상을 확인합니다.
6. 수동 기준점 탭에서 영상에 실제 보이는 관절 위치를 표시하거나 `보이지 않음`으로 표시합니다. **한 분석의 주석은 두 모델이 공유**합니다.
7. 좌표·각도 CSV와 결과 ZIP을 내려받을 수 있습니다. 원본 동영상 대신 분석 구간만 포함한 출력도 생성합니다.

추적을 길게 잃으면 다른 사람으로 자동 변경하지 않고 `reselect_required`를 표시합니다. 이 경우 유실 뒤 시점으로 분석 구간을 옮겨 다시 선택한 후 별도 분석을 실행하세요. 한 실행 안에서 중간에 사용자가 록온을 재지정하는 기능은 아직 없습니다.

## 모델

### ProbPose-s

- 원본: https://huggingface.co/vrg-prague/ProbPose-s
- 전신이 화면 밖으로 잘리는 상황을 다루는 모델. 17개 신체 지점.
- 공식 mmpretrain ViT backbone과, 공식 ProbMapHead를 따라 구성한 휴대 가능한 추론 어댑터를 사용합니다. 전체 MMPose의 훈련용/컴파일된 연산 의존성을 요구하지 않습니다.
- 공식 가중치 SHA-256을 고정 검증하고 모든 추론 파라미터를 strict 로드합니다.
- 기본 설정의 좌우 반전 평균 추론, 공식 expected-OKS 좌표 디코더, crop padding/UDP 변환과 복원을 사용합니다.
- 품질(predicted OKS), 관절 존재 확률, 가시성은 **별도 필드**입니다.
- 어댑터 head의 5개 출력은 같은 가중치·입력에서 원본 head와 최대 절대 오차 0임을 확인했습니다. `head-parity.json`에 기록했습니다. 이는 head 구현 일치 확인이며, 모델의 임상 정확도나 전체 MMPose 파이프라인 벤치마크 재현을 뜻하지 않습니다.

### RTMW-l

- OpenMMLab의 공식 RTMW-l Cocktail14 256×192 ONNX 배포본을 rtmlib로 실행합니다.
- 신체·발·얼굴·손을 포함한 133개 지점 중 화면과 CSV에는 신체·발 23개를 사용합니다.
- 이전에 조사한 Hugging Face `akore/rtmw-m-256x192`와 **다른 크기의 체크포인트**입니다. 검증 가능한 공식 ONNX 배포본을 사용했고 모델명과 출처를 결과에 명시했습니다.
- SimCC peak 점수는 가시성이나 관절 존재의 보정된 확률이 아닙니다. 없는 값을 만들어 채우지 않습니다.
- 두 모델의 품질 기준 숫자가 같아도 의미가 같지 않습니다. 기본값은 탐색용이며 수동 주석에 맞춰 조절해야 합니다.

사람 검출기는 YOLOX-tiny HumanArt입니다. 초기 선택 후 위치·박스 겹침·고정 외형 히스토그램으로 보수적으로 연결합니다. 신원 확인 모델이 아니므로 연결이 확실해 보이더라도 영상 검수가 필요합니다. 여러 사람의 겹침과 비슷한 옷에서 바뀜을 완전히 막는다는 보장은 없습니다.

## 보정 규칙

- 원본 좌표는 절대 덮어쓰지 않습니다.
- 품질/가시성/존재 확률·화면 밖 여부를 구분해 유효성을 판단합니다.
- 신체 크기와 실제 시간 간격으로 정규화한 이동량, 분절 길이 변화로 이상치 후보를 제외합니다. 빠른 실제 운동·원근 변화·카메라 움직임을 오인할 수 있으므로 기준을 조절하세요.
- 짧은 저품질/가림/이상치 구간만 앞뒤 유효 좌표로 보간합니다. 기본 최대 길이 0.25초는 **양쪽 유효점 사이의 간격**입니다.
- 화면 밖, 존재 확률 미달, 지원하지 않는 관절, 추적 유실, 긴 누락은 보간하지 않습니다. 양 끝 누락도 외삽하지 않습니다.
- 시간 기반 지수 평활화를 사용하고, 보간의 평활화 잔여 영향이 1%보다 큰 후속 좌표도 따로 표시합니다.
- 보간하거나 평활화한 좌표가 실제 관절 위치를 입증하지는 않습니다.

## 각도와 속도의 의미

- 팔꿈치/무릎: 세 점 사이의 **끼인각**(0–180°). 곧게 편 상태는 약 180°이며 임상적 굴곡각 0°와 다릅니다. 별도 임상 ROM 기준으로 자동 변환하지 않았습니다.
- 무릎 각속도: 인접한 유효 관측의 끼인각 차이 / 실제 시간 간격. 양수는 끼인각 증가이며 2D 신전에 해당하는 움직임일 수 있습니다. 보간 영향과 긴 시간/대상 유실 경계를 구분합니다.
- 체간: 어깨 중점—골반 중점 선이 **영상 수직선**에서 벗어난 각도. 공간상의 중력 수직과 같다는 보장은 없습니다. 고정된 수동 카메라 roll 보정만 지원합니다.
- 현재 카메라 움직임·원근·신체 회전에 대한 자동 3D 보정은 없습니다.
- 반복 횟수, Sit-to-Stand 단계 분류, 기울기 발생 시점 자동 판정은 후속 구현 범위입니다. 현재 그래프에서 시점을 확인할 수 있습니다.
- 체중 지지량/비율·근활성·경직 저항/등급·피로·치료 효율을 영상에서 직접 측정하거나 판정하지 않습니다.

## TAP 추적 결합 (2026-10-08 추가)

**④ TAP 결합 · Core ML** 탭에서 기존 ProbPose 분석을 선택해 실행합니다.
기존 분석은 수정하지 않고 새 출력 폴더에 A/B/C 비교를 생성합니다.

- A: ProbPose 원본
- B: ProbPose + 기존 이상치 제거·보간·평활화
- C: ProbPose + **온라인 BootsTAPIR**, 추가 보간·평활화 없음

C는 0.5초 간격(설정 가능)으로 재검출 좌표를 확인하고 사이 프레임에서는 TAP 추적을 사용합니다. 동일 입력 비교를 위해 A에서 계산한 **현재 프레임**의 관절 검출 좌표를 재사용합니다. C가 미래 프레임이나 기존 평활화 결과를 참고하지는 않습니다. 따라서 실행 시간은 검출까지 포함한 전체 실시간 처리 비용이 아닙니다.

검출과 추적이 일치하면 추적을 유지합니다. 추적이 불확실하고 검출이 확실하면 해당 관절의 특징·시간 상태를 초기화합니다. 둘 다 확실하지만 크게 다르면 평균내지 않고 측정 불가로 남기며, 다음 신뢰 가능한 재검출로 초기화하기 전까지 해당 점을 보류합니다. 충돌 이력이 없는 점은 검출이 불확실하지만 추적이 유효하면 추적을 유지합니다. 대상 유실 시 모든 추적 상태를 초기화합니다. 신원 연결은 여전히 기존 검출기 기반 휴리스틱이며, TAP 자체가 환자 신원을 보장하지 않습니다.

TAP 점수는 `(1−sigmoid(occlusion)) × (1−sigmoid(expected_dist))`입니다. ProbPose의 OKS 품질값과 같은 의미가 아닙니다. 확률처럼 출력되어도 이번 영상에서 확률 보정이 검증된 것은 아닙니다.

입력 해상도 256/512를 선택할 수 있습니다. 512는 256 단계에 더해 고해상도 refinement를 수행하며 연산량과 상태 크기가 늘어납니다. 입력은 전체 프레임을 정사각형으로 축소합니다. 근접 관절만 따로 crop하는 기능은 아직 없으며, 작은 관절에는 축소 해상도가 한계가 될 수 있습니다. 피부를 노출하면 옷 움직임의 영향은 줄지만 피부 표면의 점이 해부학적 관절 중심과 같지는 않습니다.

### 수동 입력과 평가 분리

- ④ 탭: 추적 초기화/재초기화용 수동 입력점.
- ③ 탭: 예측을 숨긴 원본 위의 평가용 기준점. `설정 조정용`과 `최종 평가용`을 구분하고 가시성·확신·촬영 조건을 기록합니다.
- 추적 입력으로 사용한 동일 프레임·관절은 **모든 방식의 정확도 평가에서 제외**합니다.
- 예전 주석에 구분 필드가 없다면 `최종 평가용`으로 불러옵니다. 이미 설정 조정에 사용했다면 해당 용도로 수정해야 합니다.
- 정확도 표에는 평균/중앙값/P95 픽셀 오차, 고정 영상 대각선 대비 오차, 큰 오차 비율, 제공률, 보이지 않는 점을 유효하게 출력한 비율, 모든 방식의 공통 유효 기준점 오차를 표시합니다. 확신 정도는 상세 CSV에 보존하며 현재 자동 가중치/제외 기준으로 사용하지 않습니다.
- 지연 비교는 움직임이 있고 0.3초 이하 간격의 연속 기준점이 8개 이상, 1초 이상 확보된 때만 탐색적으로 수행합니다. ±0.3초 범위에서 기준점과 예측 궤적의 오차가 최소인 지연을 찾습니다. 큰 가림 간격을 메우지 않습니다. 이는 임상 반응시간이 아니며 궤적 오차와 혼동될 수 있습니다.
- 수동 기준점이 없으면 **정확도 개선은 미확인**입니다. 매끄러움·유효률·검출/추적 일치는 정확도의 대체값이 아닙니다.

## Core ML 및 visionOS 최소 샘플

TAP의 **특징 추출 / 기준점 초기화 / 프레임 추적 업데이트**를 각각 Core ML로 변환했습니다. 256×256, **3개 점**, FP32, 명시적 시간 상태 입력/출력으로 제한한 최소 검증입니다. 17점·512 입력이나 ProbPose까지 포함한 전체 결합의 Core ML 실행 완료를 의미하지 않습니다.

현재 앱 환경(Torch 2.14/NumPy 2.5)과 변환 도구 조합에서 문제가 있어 별도 `.venv-coreml`(Torch 2.7/NumPy 2.2/Core ML Tools 9)을 사용합니다. grouped temporal convolution의 macOS 추적 오류, 미지원 `view_as`, rank-6 중간 텐서는 수학적으로 동일한 세 tap 합·고정 reshape·평탄화로 변환했습니다. 원본과의 출력 일치를 검증했고 변경은 export 프로세스에만 적용합니다. 여러 native 모델 변환을 한 프로세스에서 수행할 때 발생한 충돌을 피하도록 단위별 subprocess를 사용합니다. 실패 이력 로그도 보존했습니다.

```sh
uv venv .venv-coreml --python 3.12
uv pip install --python .venv-coreml/bin/python -r requirements-coreml.txt
.venv-coreml/bin/python scripts/export_all_coreml.py
./scripts/check_coreml_sequence.sh
```

- `coreml/features.mlpackage`, `query.mlpackage`, `update.mlpackage`
- `coreml/report.json`: 개별 변환 및 Mac CPU 실행 비교
- `coreml/sequence-parity.json`: **Swift Core ML로 세 모델을 연결한 연속 3프레임**과 PyTorch 결과의 비교
- 이 좌표 일치 검증은 관절 위치의 임상 정확도 검증이 아닙니다.
- Core ML 변환 성공이 Neural Engine 전체 실행이나 실시간 실행을 보장하지 않습니다.

`visionos/TAPValidation.xcodeproj`는 별도 녹화 영상용 실행 샘플입니다. Vision Pro 대상 **서명 없는 빌드**를 확인했습니다. 녹화 영상을 불러와 표면점 3개를 지정하고 추적하여 좌표·프레임 처리 시간을 CSV로 내보냅니다. CPU만 사용 / 자동 compute units를 선택할 수 있습니다. 검출·록온·주기적 ProbPose 재검출까지 연결된 앱은 아닙니다.

```sh
xcodebuild -project visionos/TAPValidation.xcodeproj -scheme TAPValidation \
  -sdk xros -destination 'generic/platform=visionOS' \
  -derivedDataPath visionos/build CODE_SIGNING_ALLOWED=NO build
```

실기기에서는 Xcode에서 팀·서명을 설정하고 실행해야 합니다. 현재 연결된 Vision Pro 실기기가 없어 실행·발열·메모리·지연 검증은 미완료입니다. 이 작업 폴더에서 메인 카메라 entitlement 설정은 확인되지 않아 라이브 카메라 입력을 임의로 연결하지 않았습니다. 샘플은 녹화 영상 입력으로 명확히 구분합니다.

## 보정 규칙 v2와 전체 구간 검토

`⑤ 보정 규칙 · 전체 검토`에서 선택한 ProbPose RAW를 재처리합니다. 기존 보정은 유지하고 `ProbPose-v2`를 새 분석 폴더에 추가합니다. 현재 예시 결과는 `outputs/20261008-193739-590291`입니다. STS 14–34초의 **200개 분석 프레임**을 모두 검사했으며, 전체 원본 영상/모든 원본 프레임 검증은 아닙니다.

- 기존 규칙은 최근 **채택한 길이** 중앙값에서 65% 이상 변하면 연결선의 두 번째 점을 제거했습니다. 기준이 초기 자세에 머물고, 어느 끝점이 잘못됐는지 구분하지 않는 문제가 있었습니다.
- v2는 최근 1초의 기본 품질 기준을 통과한 RAW 길이를 사용합니다. 길이 이상만으로 관절점을 제거하지 않고 연결선 경고를 남깁니다.
- 보이는 신체 점들의 중앙값 이동을 제외한 개별 움직임을 검사합니다. 영상상 신체 크기 대비 최소 이동/속도 기준, 최근 이동의 중앙값·MAD, 상대 끝점과의 차이를 함께 사용합니다. 공통 이동 추정은 환자와 카메라 이동을 분리하지 않으며, 카메라 회전/원근/줌을 해결하지 않습니다.
- 한쪽 끝점의 독립적인 움직임 이상과 구간 길이 이상이 함께 있고 상대 끝점보다 크게 튀는 경우에만 그 점을 제외합니다. 이 조건도 실험적 휴리스틱이며 실제 오류를 확정하지 않습니다.
- 움직임/품질이 애매한 점은 **노란 표시**로 남기고 측정용 좌표에서는 제외합니다. 길이 경고는 노란 점선이며 해당 연결선에 의존하는 각도·각속도는 제외합니다. `*_display_deg`는 길이 경고 제외 전의 참고값이며 측정 결과로 사용하지 않습니다.
- 짧은 보간·평활화 조건은 유지합니다. 새 구조/움직임 경고는 보간하지 않습니다. 화면 밖/대상 유실/존재 가능성이 낮은 점은 복원하지 않습니다.

전체 프레임별 후보는 `review_frames.csv`, 44개 검토 표본은 `review_queue.csv`에 있습니다. 위험 구간 대표뿐 아니라 1초 간격과 고정 난수 표본도 포함합니다. 기본 예시에서 171개 프레임이 후보로 표시되었는데, **이 수치는 오류 프레임 수가 아닙니다.** 낮은 품질·보정 차이·경고 등이 있는 광범위한 검토 대상입니다.

⑤ 탭에서 원본/기존 보정/v2를 확인하고 관절별 원인과 정성 판단을 기록할 수 있습니다. ③ 탭에서 예측을 숨긴 원본에 평가 기준점을 입력하면 RAW/기존 보정/v2를 같은 기준점으로 비교합니다. 이미 살펴본 사례 주변과 조정용 시간 블록은 최종 평가에서 제외합니다. 최종 평가용 기준점을 보고 다시 규칙을 조정했다면 해당 데이터는 조정용으로 옮기고 새로운 평가 구간/영상을 확보해야 합니다.

좌표 제공률, 삭제 건수, 화면 매끄러움은 정확도의 정답이 아닙니다. 아직 수동 기준점이 없어 정확도 개선은 미확인입니다. 골반 중심과 가려진 관절은 육안 주석 자체도 불확실할 수 있습니다.
